## Lab architecture

The performance lab (`infrastructure/docker-compose.loadtest.yml`) is a
self-contained, isolated copy of the production-shaped stack: PostgreSQL
(pgvector), Redis, the Spring Boot backend under test, and a **wire-compatible
Gemini mock** (`infrastructure/gemini-mock`, a small Go service) that replaces
the real `generativelanguage.googleapis.com` so external AI latency is removed
from the variable set and replaced with a *deterministic, programmable*
distribution. The mock samples each request's latency independently from a
seeded RNG (default: ~600ms body + jitter, with a 5% long tail of 6-9s and an
optional injected failure rate), which is what makes the request-hedging
experiment reproducible. Load is generated by **k6** (open-model
constant/ramping arrival rate) and every signal is captured in **Prometheus**
(5s scrape of the backend's `/actuator/prometheus`, the mock's `/metrics`, and
postgres/redis exporters; k6 results stream in via remote-write) and visualised
in **Grafana**. The lab is fully decoupled from the dev compose stack (distinct
`-lab` container names, its own `auralab` network, ephemeral volumes) so it can
be torn up and down without touching developer data.

```
 k6 (open model) ──HTTP──▶ backend:8080 ──▶ postgres / redis
        │                      │
        │ remote-write         └──▶ gemini-mock:8089 (programmable latency)
        ▼                              (Gemini generateContent + embeddings)
   prometheus:9090 ◀── scrape ── backend /actuator/prometheus
        │            ◀── scrape ── gemini-mock /metrics
        │            ◀── scrape ── postgres-exporter / redis-exporter
        ▼
   grafana:3000 (Aura Fitness — Load Test Overview)
```

## How to reproduce

From `infrastructure/`:

```bash
# Validate + bring the lab up
docker compose -f docker-compose.loadtest.yml config
docker compose -f docker-compose.loadtest.yml up -d --build

# Smoke check
docker compose -f docker-compose.loadtest.yml --profile load \
  run -e BACKEND_URL=http://backend:8080 k6 run /scripts/smoke.js
```

See `infrastructure/loadtest/README.md` and `infrastructure/loadtest/k6/README.md`
for the full per-experiment commands.

Measurement convention: read P50/P95/P99 from Grafana (panel "HTTP latency
percentiles") over the steady-state window of each run, or from k6's end-of-run
summary (`aura_*_latency_ms`). **delta** = after − before (negative is an
improvement for latency).
